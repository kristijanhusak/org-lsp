What to try in Helix to know that everything org-lsp does works
there. The keys are the defaults. Tick a box once it works; a check that
fails is a bug to report. [[file:../../docs/helix.org][docs/helix.org]] says what is left out
here and why.

To look at most of what a file shows at once (highlighting, concealing,
entities, folding when it opens, indentation, shrunk columns,
diagnostics), open [[file:../../tests/visual.org][tests/visual.org]]: each of
its sections says what it should look like.

* Setup

- [ ] Installed with ~install.sh helix~: Org is in =~/.config/helix/languages.toml= with ~show_document = true~ and ~message_requests = false~ in its ~config~, and an Org file starts the server
- [ ] Code actions (~Space a~) list the Org commands where they apply
- [ ] A command that asks for a choice says ~PROMPT: pick the answer from the code actions~, and the choices come first in the code actions; one that asks for text says ~PROMPT: answer with a rename at the cursor~, and ~Space r~ answers
- [ ] Inlay hints show with ~display-inlay-hints = true~

* Highlighting

*Not in Helix:* Helix does not use semantic tokens: it colors Org with its own tree-sitter grammar.

* Folding and visibility

*Not in Helix:* Helix has no folding.

* Headings and structure

*Partly:* Moving between headings, ~org-goto~ and Org's ~C-a~, ~C-e~, ~C-k~ and ~C-y~ are left out: they need keys, and Helix cannot bind a key to a server's command; nor are the commands run by Emacs (~C-c *~, ~C-c ;~, cloning) among its code actions. New headings are code actions.

- [ ] On a headline, a new heading of the same level goes below: the code action /New heading, item or table row/
- [ ] A new TODO heading: the code action /New TODO heading, or item with a checkbox/
- [ ] A new heading after the subtree, and a TODO one: the code action /New heading after the subtree/, the code action /New TODO heading after the subtree/
- [ ] Promoting and demoting a heading; its tags stay aligned: the code action /Promote the heading; outdent the item; move the table column left/, the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/
- [ ] Promoting and demoting a subtree: the code action /Promote the subtree; outdent the item with its children; delete the table column/, the code action /Demote the subtree; indent the item with its children; insert a table column/
- [ ] Moving a subtree up and down past its siblings: the code action /Move the subtree, the item or the table row up/, the code action /Move the subtree, the item or the table row down/
- [ ] Inserting an inline task gives 15 stars and an ~END~ line; demoting it changes both; the outline leaves it out, and folding it hides its text and its ~END~ line: the code action /Insert an inline task/, the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/
- [ ] Cutting a subtree and pasting it under another heading: its level fits there: the code action /Cut the subtree/, the code action /Paste the subtree/
- [ ] Copying a subtree and pasting it: the code action /Copy the subtree/, the code action /Paste the subtree/
- [ ] With ~org_allow_promoting_top_level_subtree~ on, promoting ~* A~ makes it ~# A~: the code action /Promote the heading; outdent the item; move the table column left/
- [ ] Sorting the children of a heading alphabetically, then by TODO state: the code action /Sort the entries, the items or the table rows/
- [ ] The outline lists the headings nested, also in pickers that filter symbols by kind: ~Space s~

- [ ] Indenting and outdenting an item; and with its children: the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/, the code action /Promote the heading; outdent the item; move the table column left/, the code action /Demote the subtree; indent the item with its children; insert a table column/, the code action /Promote the subtree; outdent the item with its children; delete the table column/
- [ ] Moving an item up and down: the code action /Move the subtree, the item or the table row up/, the code action /Move the subtree, the item or the table row down/
- [ ] Toggling a checkbox: its parent box and the ~[1/3]~ cookie follow: the code action /Toggle the checkbox/
- [ ] On a list numbered 1, 3, 2, the same command renumbers and repairs it: the code action /Toggle the checkbox/
- [ ] Sorting a list's items alphabetically: the code action /Sort the entries, the items or the table rows/

* TODO keywords

*Partly:* States are picked from the code actions, where they come first once asked for; for a note for a state change (~@~), the answer is typed as a rename at the cursor (~Space r~), as Helix has no box of its own for a server to ask for text. Faces of particular keywords and priorities are not shown.

- [ ] With ~org_enforce_todo_dependencies~, a parent with a child not done cannot be done: the change is refused with ~blocked (by "TODO Child")~; with ~org_enforce_todo_checkbox_dependencies~, an entry with an unchecked box cannot either: the code action /Change the TODO state/
- [ ] Those tasks are dimmed in the agenda and the TODO list
- [ ] Changing the TODO state of a headline (with ~org_todo_keywords~ keys, picked by key): the code action /Change the TODO state/
- [ ] Cycling to the next and previous state: the code action /Cycle TODO state forward/, the code action /Cycle TODO state backward/
- [ ] Done with ~org_log_done = "time"~ writes ~CLOSED: [...]~ below the headline: the code action /Change the TODO state/
- [ ] A state with ~@~ (~WAIT(w@)~) asks for a note, written below the headline: the code action /Change the TODO state/
- [ ] Done on a repeating entry (~<2026-01-01 Thu +1w>~) moves its date a week on and keeps it TODO: the code action /Change the TODO state/
- [ ] The parent's ~[1/2]~ cookie is recounted: the code action /Change the TODO state/
- [ ] A ~#+TODO: A B | C~ line in the file is used instead of the settings: the code action /Change the TODO state/
- [ ] With ~#+TODO: TODO | DONE~ and ~#+TODO: REPORT BUG | FIXED~, changing the state without keys goes ~BUG~, ~FIXED~, none, then back to ~REPORT~: the code action /Change the TODO state/
- [ ] Switching to the next and previous keyword set says ~Keyword-Set 2/2: REPORT BUG FIXED~: the code action /Switch to the next TODO keyword set/, the code action /Switch to the previous TODO keyword set/

* Dates and times

*Partly:* Dates are typed (~+2d~, ~fri 10:00~), with no calendar: the answer is typed as a rename at the cursor (~Space r~), as Helix has no box of its own for a server to ask for text; Helix reads no file again that the server writes, as the calendar is. New timestamps are left out: they are not among Helix's code actions. Changing a timestamp works.

- [ ] Scheduling with ~+2d~: ~SCHEDULED: <…>~ goes below the headline: the code action /Schedule the entry/

- [ ] On a timestamp, changing the day, month, year, hour and minute under the cursor; with a count: the code action /Increase the part of the timestamp at the cursor/, the code action /Decrease the part of the timestamp at the cursor/

* Agenda

Follow mode, the outline path of the cursor's entry and the entry in another window are left out: Helix tells a server no cursor moves, and knows no other window of the server's. Column view in the agenda is left out: it draws over the lines. The server's edits leave the agenda's buffer changed: ~:buffer-close!~ closes it.

- [ ] The agenda menu lists the views and the custom commands: the code action /Agenda commands/
- [ ] The week view: scheduled entries, deadlines with their warnings, the time grid: the code action /Agenda for the current week or day/
- [ ] Later, earlier, today; day, week, month views; going to a date: the code action /Agenda: go forward in time/, the code action /Agenda: go backward in time/, the code action /Agenda: go to today/, the code action /Agenda: day view/, the code action /Agenda: week view/, the code action /Agenda: month view/, the code action /Agenda: go to a date/
- [ ] The TODO list, a tag search (~work+urgent~), a word search: the code action /Agenda commands/

- [ ] With ~org_agenda_prefix_format~ ~{ todo = " %-12:c%-4(org-entry-get nil "EFFORT") " }~, the TODO list shows each entry's effort after its category, ~nil~ without one (needs Emacs): the code action /List of all TODO entries/
- [ ] Going to the line's entry, and back to the agenda where its cursor was (~Space b~): the code action /Agenda: go to the entry/
- [ ] Changing the line's TODO state and priority; the line follows: the code action /Change the TODO state/, the code action /Raise the priority/
- [ ] Scheduling the line's entry and setting its deadline: the code action /Schedule the entry/, the code action /Set the deadline of the entry/
- [ ] Setting the line's tags, adding a note, refiling, archiving: the code action /Set the tags of the headline/, the code action /Add a note to the entry/, the code action /Refile the entry/, the code action /Archive with the default command/
- [ ] Filters by tag, category and effort, and removing them: the code action /Agenda: filter by tag/, the code action /Agenda: filter by the line's category/, the code action /Agenda: filter by effort/, the code action /Agenda: remove all filters/
- [ ] Marking lines and a bulk action on them: the code action /Agenda: mark the entry for a bulk action/, the code action /Agenda: an action on the marked entries/
- [ ] Entry text, log mode, the clock report, archives mode: the code action /Agenda: entry text mode, some text of each entry under its line/, the code action /Agenda: log mode, what was closed and clocked/, the code action /Agenda: the clock report/, the code action /Agenda: include archived trees/
- [ ] In the week view, inactive timestamps show after ~[~ with /Display now includes inactive timestamps as well/, marked ~[~, and are gone again when the agenda is rebuilt: the code action /Agenda: search for another word, or show inactive timestamps/, the code action /Agenda: show inactive timestamps once/, the code action /Agenda: rebuild/

- [ ] Adding today's appointments: an entry timed a few minutes from now is reminded of every three minutes until it is due (needs Emacs): the code action /Add today's appointments from the agenda files/
