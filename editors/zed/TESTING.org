#+title: Testing org-lsp in Zed by hand
#+options: ^:{}

# Written by scripts/generate-docs.mjs from scripts/features.mjs.

What to try in Zed to know that everything org-lsp does works
there. The keys are the defaults. Tick a box once it works; a check that
fails is a bug to report. [[file:../../docs/zed.org][docs/zed.org]] says what is left out
here and why.

To look at most of what a file shows at once (highlighting, concealing,
entities, folding when it opens, indentation, shrunk columns,
diagnostics), open [[file:../../tests/visual.org][tests/visual.org]]: each of
its sections says what it should look like.

* Setup

- [ ] Installed with ~install.sh zed~: after a restart the extension starts the server put beside it, and Org's keys run the agenda (~ctrl-c a~)
- [ ] ~"semantic_tokens": "combined"~ and inlay hints on for Org in the settings
- [ ] Code actions (~ctrl-.~) list the Org commands where they apply
- [ ] The keymap and tasks from docs/keys/zed.org run the agenda's commands by key

* Highlighting

*Partly:* Links, emphasis markers, pretty entities and sub- and superscripts are not concealed: Zed lets no server hide text. The colors need ~"semantic_tokens": "combined"~; code blocks take their language's colors, inline code does not.

- [ ] Headlines are colored by level; TODO and DONE keywords, priorities (~[#A]~) and tags have colors of their own
- [ ] ~*bold*~, ~/italic/~, ~_underline_~, ~+strike+~, ~=verbatim=~ and =~code~= are colored
- [ ] Timestamps, ~SCHEDULED:~ and ~DEADLINE:~, ~CLOCK:~ lines, drawers, ~#+~ keywords and ~#~ comments are colored
- [ ] A ~#+begin_src python~ block shows its code in Python's colors
- [ ] Table rules and bars, footnotes (~[fn:1]~), ~<<targets>>~, macros (~{{{x}}}~) and entities (~\alpha~) are colored
- [ ] A subtree tagged ~:ARCHIVE:~ is shaded

* Folding and visibility

*Partly:* Zed folds with its own folding: Org's cycling and sparse trees need folds an extension can set, which Zed does not offer.

- [ ] On a headline, cycling goes folded → children → subtree
- [ ] Cycling the whole file goes overview → contents → everything
- [ ] Narrowing to the subtree opens it in a file of its own; saving that file writes it back into the Org file and saves it: the code action /Narrow to the subtree: it in a file of its own/
- [ ] Widening in the narrowed file writes it back and closes it (~C-c '~ there does the same): the code action /Widen: the narrowed file written back and closed/
- [ ] Zed's own folds open and close on headlines, drawers and blocks

* Headings and structure

*Partly:* Cloning is left out: it asks for text, and Zed cannot ask for text on a server's behalf. A command on a selection acts on the cursor's line: Zed tells a server no selection. The rest goes through the keys of keymap.json (Zed's tasks).

- [ ] On a headline, a new heading of the same level goes below: the code action /New heading, item or table row/
- [ ] A new TODO heading: the code action /New TODO heading, or item with a checkbox/
- [ ] A new heading after the subtree, and a TODO one: the code action /New heading after the subtree/, the code action /New TODO heading after the subtree/
- [ ] Promoting and demoting a heading; its tags stay aligned: the code action /Promote the heading; outdent the item; move the table column left/, the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/
- [ ] Promoting and demoting a subtree: the code action /Promote the subtree; outdent the item with its children; delete the table column/, the code action /Demote the subtree; indent the item with its children; insert a table column/
- [ ] Moving a subtree up and down past its siblings: the code action /Move the subtree, the item or the table row up/, the code action /Move the subtree, the item or the table row down/
- [ ] Cutting a subtree and pasting it under another heading: its level fits there: the code action /Cut the subtree/, the code action /Paste the subtree/
- [ ] Copying a subtree and pasting it: the code action /Copy the subtree/, the code action /Paste the subtree/
- [ ] Sorting the children of a heading alphabetically, then by TODO state: the code action /Sort the entries, the items or the table rows/
- [ ] Moving to the next and previous heading; with a count, that many: the code action /Move to the next heading/, the code action /Move to the previous heading/
- [ ] Moving to the next and previous heading of the same level, stopping at the parent's end: the code action /Move to the next heading of the same level/, the code action /Move to the previous heading of the same level/
- [ ] Moving to the parent heading; on a top heading Org says it is at the top level: the code action /Move to the parent heading/
- [ ] Going to a heading picked by its outline path (~A/B/~): the code action /Go to a heading of the file/
- [ ] Off a table, turning a line into a heading and back (needs Emacs): the code action /Recalculate the table's current line/
- [ ] Toggling ~COMMENT~ on the heading (needs Emacs): the code action /Toggle the COMMENT keyword of the heading/
- [ ] The outline lists the headings nested, also in pickers that filter symbols by kind: the outline panel

* Lists and checkboxes

*Partly:* ~RET~ stays Zed's own, and so do Shift and Alt with the arrows, which cycle bullets and move items in Org.

- [ ] On an item, the next item goes below; in a numbered list the numbers go on, after a checkbox item the new one has ~[ ]~: the code action /New heading, item or table row/
- [ ] Indenting and outdenting an item; and with its children: the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/, the code action /Promote the heading; outdent the item; move the table column left/, the code action /Demote the subtree; indent the item with its children; insert a table column/, the code action /Promote the subtree; outdent the item with its children; delete the table column/
- [ ] Moving an item up and down: the code action /Move the subtree, the item or the table row up/, the code action /Move the subtree, the item or the table row down/
- [ ] Toggling a checkbox: its parent box and the ~[1/3]~ cookie follow: the code action /Toggle the checkbox/
- [ ] On a list numbered 1, 3, 2, the same command renumbers and repairs it: the code action /Toggle the checkbox/
- [ ] Sorting a list's items alphabetically: the code action /Sort the entries, the items or the table rows/
- [ ] Off a table, turning lines into items and back (needs Emacs); in a table the same key inserts a rule below the row: the code action /Insert a rule below the table row/

* TODO keywords

*Partly:* A note for a state change (~@~) cannot be typed: Zed cannot ask for text on a server's behalf. States are picked with buttons. Faces of particular keywords and priorities are not shown: Zed colors tokens by its theme only.

- [ ] With ~org_enforce_todo_dependencies~, a parent with a child not done cannot be done: the change is refused with ~blocked (by "TODO Child")~; with ~org_enforce_todo_checkbox_dependencies~, an entry with an unchecked box cannot either: the code action /Change the TODO state/
- [ ] Those tasks are dimmed in the agenda and the TODO list
- [ ] Changing the TODO state of a headline (with ~org_todo_keywords~ keys, picked by key): the code action /Change the TODO state/
- [ ] Cycling to the next and previous state: the code action /Cycle TODO state forward/, the code action /Cycle TODO state backward/
- [ ] Done with ~org_log_done = "time"~ writes ~CLOSED: [...]~ below the headline: the code action /Change the TODO state/
- [ ] Done on a repeating entry (~<2026-01-01 Thu +1w>~) moves its date a week on and keeps it TODO: the code action /Change the TODO state/
- [ ] The parent's ~[1/2]~ cookie is recounted: the code action /Change the TODO state/
- [ ] A ~#+TODO: A B | C~ line in the file is used instead of the settings: the code action /Change the TODO state/
- [ ] With ~#+TODO: TODO | DONE~ and ~#+TODO: REPORT BUG | FIXED~, changing the state without keys goes ~BUG~, ~FIXED~, none, then back to ~REPORT~: the code action /Change the TODO state/
- [ ] Switching to the next and previous keyword set says ~Keyword-Set 2/2: REPORT BUG FIXED~: the code action /Switch to the next TODO keyword set/, the code action /Switch to the previous TODO keyword set/

* Priorities

- [ ] Raising and lowering the priority of a headline: the code action /Raise the priority/, the code action /Lower the priority/
- [ ] Setting it by key; ~SPC~ removes it: the code action /Set the priority/
- [ ] ~#+PRIORITIES: 1 5 3~ makes the priorities numbers: the code action /Raise the priority/

* Tags

*Partly:* Setting tags is left out: it needs keys pressed in turn, or typed tags, and Zed cannot ask for text on a server's behalf. Completion and renaming work.

- [ ] Tags are completed after ~:~ at the end of a headline
- [ ] Renaming a tag renames it in every headline and ~#+FILETAGS:~: ~F2~ on the tag

* Properties and column view

*Partly:* Setting a property or the effort is left out: they are typed, and Zed cannot ask for text on a server's behalf. Column view is left out: it draws over the headlines.

- [ ] On a property line with ~NAME_ALL~, cycling through its values: the code action /Move the date a day later, or cycle the TODO state or the list's bullets forward/, the code action /Move the date a day earlier, or cycle the TODO state or the list's bullets backward/
- [ ] Deleting a property from the entry, and from the whole file: the code action /Delete a property of the entry/, the code action /Delete a property from every entry of the file/
- [ ] Toggling ~ORDERED~: the code action /Toggle whether subtasks must be done in order (ORDERED)/
- [ ] Property names are completed in a drawer

* Dates and times

*Partly:* Scheduling, deadlines and new timestamps are left out: they ask for a date, and Zed cannot ask for text on a server's behalf. Changing a timestamp works.

- [ ] Removing the scheduled date and the deadline: the code action /Remove the scheduled date of the entry/, the code action /Remove the deadline of the entry/
- [ ] On a timestamp, changing the day, month, year, hour and minute under the cursor; with a count: the code action /Increase the part of the timestamp at the cursor/, the code action /Decrease the part of the timestamp at the cursor/
- [ ] Moving a timestamp by days: the code action /Move the date one day later/, the code action /Move the date one day earlier/
- [ ] A repeater (~+1w~) and a warning (~-2d~) are kept as the date changes

* Agenda

*Partly:* The agenda is a file, its commands code actions (or keys through Zed's tasks); searches, going to a date and dates asked for are left out (Zed cannot ask for text on a server's behalf), and follow mode (Zed reports no cursor moves to an extension). Column view in the agenda is left out: it draws over the lines.

- [ ] The agenda menu lists the views and the custom commands: the code action /Agenda commands/
- [ ] The week view: scheduled entries, deadlines with their warnings, the time grid: the code action /Agenda for the current week or day/
- [ ] Later, earlier, today; day, week, month views; going to a date: the code action /Agenda: go forward in time/, the code action /Agenda: go backward in time/, the code action /Agenda: go to today/, the code action /Agenda: day view/, the code action /Agenda: week view/, the code action /Agenda: month view/, the code action /Agenda: go to a date/
- [ ] Going to the line's entry in another window, and where the agenda is: the code action /Agenda: go to the entry in another window/, the code action /Agenda: go to the entry/
- [ ] Changing the line's TODO state and priority; the line follows: the code action /Change the TODO state/, the code action /Raise the priority/
- [ ] Marking lines and a bulk action on them: the code action /Agenda: mark the entry for a bulk action/, the code action /Agenda: an action on the marked entries/
- [ ] Entry text, log mode, the clock report, archives mode: the code action /Agenda: entry text mode, some text of each entry under its line/, the code action /Agenda: log mode, what was closed and clocked/, the code action /Agenda: the clock report/, the code action /Agenda: include archived trees/
- [ ] Hovering a line shows its entry: the mouse
- [ ] Rebuilding the agenda, saving the changed files, quitting: the code action /Agenda: rebuild/, the code action /Save all Org files/
- [ ] An entry changed in its file shows in the agenda when it is rebuilt
- [ ] Adding today's appointments: an entry timed a few minutes from now is reminded of every three minutes until it is due (needs Emacs): the code action /Add today's appointments from the agenda files/
- [ ] Pressing ~f~ many times in a row moves the agenda a week each time, in the editor too
- [ ] With no Org file open and no server running, the /Org: Agenda for the current week or day/ task opens the Org file last opened and the agenda
- [ ] Zed started again with the agenda's tab open shows the current week there, and its keys work
- [ ] ~ctrl-c a~ in an Org file asks for the agenda view with buttons; ~ctrl-c c~ captures

* Clocking

*Partly:* No clock in the status line: Zed has no place there for an extension's text.

- [ ] Clocking into an entry whose effort its time passes shows ~Task ‘…’ should be finished by now. (0:30)~, once: the code action /Clock in/
- [ ] Clocking in: ~:LOGBOOK:~ gets a ~CLOCK:~ line and the clock shows (~[0:01] (Task)~): the code action /Clock in/
- [ ] Clocking out writes the end and the duration: the code action /Clock out/
- [ ] Cancelling the clock takes its line out: the code action /Cancel the clock/
- [ ] Going to the clocked entry from another file: the code action /Go to the clocked entry/
- [ ] Clocking in the last entry again: the code action /Clock in the last clocked task/
- [ ] The time clocked under each headline shows next to it: the code action /Show the time clocked under each headline/
- [ ] A clock table: inserted, then updated; shifting its ~:block~ on the ~#+BEGIN:~ line: the code action /Insert or update a clock table/, the code action /Update the dynamic block/
- [ ] A clock left running when the editor closed is offered for resolving on the next start: the code action /Resolve a dangling clock/
- [ ] In the agenda, clocking in and out; the clocked line is highlighted from edge to edge: the code action /Clock in/, the code action /Clock out/

* Capture

*Partly:* Templates with prompts are left out: Zed cannot ask for text on a server's behalf. The capture buffer's tab stays open once the entry is filed: Zed lets no server close a tab.

- [ ] The menu lists the templates by key: the code action /Capture/
- [ ] An entry template opens the capture buffer with the cursor at ~%?~: the code action /Capture/
- [ ] Finishing puts the entry under its target: the code action /Capture: finish/
- [ ] Aborting leaves the target unchanged: the code action /Capture: abort/
- [ ] A date tree target files under year, month and day: the code action /Capture/
- [ ] ~%a~ links back to where the capture started: the code action /Capture/
- [ ] ~%c~ puts in what was copied last (in Neovim and Vim, the register the key was typed with): the code action /Capture/
- [ ] ~%[snippet.txt]~ puts in the file's text, relative to the file captured from: the code action /Capture/
- [ ] ~%(upcase "abc")~ puts in ~ABC~, what Emacs makes of it (needs Emacs): the code action /Capture/

* Refile and archive

- [ ] Refiling a subtree under a heading of the same file, and of another file: the code action /Refile the entry/
- [ ] Archiving a subtree: it goes to ~FILE_archive~ with its ~ARCHIVE_…~ properties: the code action /Archive the subtree/
- [ ] Archiving to the archive sibling: the code action /Archive the subtree under its Archive sibling/
- [ ] Toggling the ~ARCHIVE~ tag: the code action /Toggle the ARCHIVE tag/
- [ ] Archiving every done subtree after confirming each: the code action /Archive the subtrees without open TODO items/
- [ ] In the agenda: archiving the line's entry; archives mode shows archived entries: the code action /Archive with the default command/, the code action /Agenda: include archived trees/

* Links

*Partly:* Storing and inserting links are left out: they ask for text, and Zed cannot ask for text on a server's behalf; moving between links needs a key. Following works through go to definition, for links inside Org files and to files.

- [ ] A ~#+LINK: gh https://github.com/%s~ line makes ~[[gh:org-lsp]]~ follow ~https://github.com/org-lsp~; ~org_link_abbrev_alist~ does the same from the settings: the code action /Open the link or thing at the cursor/
- [ ] Following a link to a headline, a custom ID and a ~<<target>>~: the code action /Open the link or thing at the cursor/
- [ ] Following a ~file:~ link with a search (~file:notes.org::*Heading~) and an ~id:~ link: the code action /Open the link or thing at the cursor/
- [ ] Go to definition on a link does the same: ~F12~
- [ ] Creating an ID for the entry: the code action /Create an ID for the entry/
- [ ] In ~[[~, file names, headlines and custom IDs are completed
- [ ] Hovering a link shows where it leads
- [ ] References on a headline list the links to it, in every file
- [ ] Renaming a headline updates the links that search for it
- [ ] Workspace symbols find headlines of every file

* Footnotes

*Partly:* Making footnotes and their menu are left out: they are not among Zed's code actions. Following them works.

- [ ] Following ~[fn:1]~ goes to its definition, and from the definition back to the reference: the code action /Open the link or thing at the cursor/
- [ ] A reference without a definition is reported

* Tables

*Partly:* Moving between fields with ~TAB~ and copying down (~S-RET~) are left out: those keys stay Zed's own. Creating a table is left out: it asks for its size, and Zed cannot ask for text on a server's behalf. A shrunk column shows its whole text and ~…~: Zed lets no server hide text.

- [ ] Shrinking a column with a ~<5>~ cookie puts ~…~ after each of its fields, their text left whole; again, the ~…~ go; a file with ~#+STARTUP: shrink~ opens with them: the code action /Shrink or expand the table column/
- [ ] Formatting the file aligns the tables: editor: format
- [ ] Moving a column left and right, a row up and down: the code action /Promote the heading; outdent the item; move the table column left/, the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/, the code action /Move the subtree, the item or the table row up/, the code action /Move the subtree, the item or the table row down/
- [ ] Inserting and deleting a column and a row: the code action /Demote the subtree; indent the item with its children; insert a table column/, the code action /Promote the subtree; outdent the item with its children; delete the table column/, the code action /Insert a table row above/, the code action /Delete the table row/
- [ ] A rule below the row; a rule and a move to the row below: the code action /Insert a rule below the table row/, the code action /Insert a rule below the table row and go below it/
- [ ] Blanking the field: the code action /Blank the table field/
- [ ] The sum of the column and the field's references are shown as messages (needs Emacs): the code action /Sum the numbers of the table column/, the code action /Show the references of the table field/
- [ ] Sorting the rows by the cursor's column: the code action /Sort the entries, the items or the table rows/
- [ ] The ~#+TBLFM:~ line follows a moved column

* Table formulas

- [ ] ~#+TBLFM: $3=$1*$2~ fills the third column: the code action /Recalculate the table/
- [ ] Recalculating the cursor's line only: the code action /Recalculate the table's current line/
- [ ] ~C-c C-c~ on the ~#+TBLFM:~ line applies it: the code action /Toggle the checkbox/
- [ ] A range sum ~@>$2=vsum(@2..@-1)~ and a format ~;%.2f~
- [ ] Date arithmetic (~$2=$1+7~) on timestamps
- [ ] Iterating until the table is stable: the code action /Recalculate the table until it does not change/
- [ ] An Emacs Lisp formula ~$3='(+ $1 $2);N~ and a remote reference ~remote(name,@1$1)~ are computed by Emacs (needs Emacs): the code action /Recalculate the table/
- [ ] With the formula debugger on, recalculating shows each formula's substitution history and asks whether to go on (needs Emacs): the code action /Turn the formula debugger on or off/

* Code blocks (Babel)

*Partly:* Only tangling, the block at the cursor and editing it in a file of its own are offered (code actions in a block): the file's and the subtree's evaluation, removing results and moving between blocks need keys, which Zed cannot give a server.

- [ ] Tangling writes each block to its ~:tangle~ file, ~:mkdirp~ and ~:shebang~ applied: the code action /Tangle the file's code blocks/
- [ ] A ~:tangle (concat "out" ".el")~ block is tangled by Emacs to ~out.el~ (needs Emacs): the code action /Tangle the file's code blocks/
- [ ] After tangling a block with ~:comments link~ and changing its code in the tangled file, detangling puts the new code back into the block (needs Emacs): the code action /Put the code of a tangled file back into its blocks/
- [ ] Evaluating an ~emacs-lisp~ block asks first (yes or no), then puts ~#+RESULTS:~ below it (needs Emacs): the code action /Evaluate the code block or call at the cursor through Emacs/
- [ ] ~src_emacs-lisp{(* 6 7)}~ gets ~{{{results(=42=)}}}~; a ~#+CALL:~ line its results: the code action /Evaluate the code block or call at the cursor through Emacs/
- [ ] Typing in the file while a slow block runs: the results are dropped with a warning
- [ ] Editing a code block in a file of its own: the file has the language's extension, its lines unindented and ~,*~ unescaped; saving it writes the block back and saves the Org file; the same block again shows the same file (needs Emacs): the code action /Edit the block in a file of its own/

* Diagnostics (org-lint)

- [ ] A heading in a paragraph (~text ** heading~), a link to nowhere and a block left open are reported

- [ ] ~org_lint_ignore = ["link-to-local-file"]~ silences that checker
