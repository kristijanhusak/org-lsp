#+title: Testing org-lsp in Zed by hand
#+options: ^:{}

# Written by scripts/generate-docs.mjs from scripts/features.mjs.
# Ticked boxes are kept when it is written again.

What to try in Zed to know that everything org-lsp does works
there. The keys are the defaults. Tick a box once it works; a check that
fails is a bug to report. [[file:../../docs/zed.org][docs/zed.org]] says what is left out
here and why.

To look at most of what a file shows at once (highlighting, concealing,
entities, folding when it opens, indentation, shrunk columns,
diagnostics), open [[file:../../tests/visual.org][tests/visual.org]]: each of
its sections says what it should look like.

* Setup

- [ ] Installed with ~install.sh zed~: after a restart the extension starts the server put beside it, and Org's keys run the agenda (~ctrl-c a~)
- [ ] ~"semantic_tokens": "combined"~ and inlay hints on for Org in the settings
- [ ] Code actions (~ctrl-.~) list the Org commands where they apply
- [ ] The keymap and tasks from docs/keys/zed.org run the agenda's commands by key

* Highlighting

*Partly:* Links, emphasis markers, pretty entities and sub- and superscripts are not concealed: Zed lets no server hide text. The colors need ~"semantic_tokens": "combined"~; code blocks take their language's colors, inline code does not. A headline's look does not go on to the edge of the window (~org_fontify_whole_heading_line~): Zed lets no server color a line past its text.

- [ ] Headlines are colored by level; TODO and DONE keywords, priorities (~[#A]~) and tags have colors of their own
- [ ] With ~org_fontify_todo_headline = true~ the text of a TODO headline, and with ~org_fontify_quote_and_verse_blocks = true~ the lines of a quote block, take a look of their own
- [ ] With ~org_n_level_faces = 2~, a headline of level 3 has the color of level 1; with ~org_cycle_level_faces = false~ too, that of level 2
- [ ] ~*bold*~, ~/italic/~, ~_underline_~, ~+strike+~, ~=verbatim=~ and =~code~= are colored
- [ ] With ~org_emphasis_alist = { "*": ["bold", "italic"] }~, ~*this*~ is bold and italic and ~/that/~ plain; with ~org_fontify_emphasized_text = false~ neither has a look
- [ ] Timestamps, ~SCHEDULED:~ and ~DEADLINE:~, ~CLOCK:~ lines, drawers, ~#+~ keywords and ~#~ comments are colored
- [ ] A ~#+begin_src python~ block shows its code in Python's colors
- [ ] Table rules and bars, footnotes (~[fn:1]~), ~<<targets>>~, macros (~{{{x}}}~) and entities (~\alpha~) are colored
- [ ] A subtree tagged ~:ARCHIVE:~ is shaded

* Folding and visibility

*Partly:* Zed folds with its own folding: Org's cycling and sparse trees need folds an extension can set, which Zed does not offer.

- [ ] On a headline, cycling goes folded → children → subtree
- [ ] Narrowing to the subtree opens it in a file of its own; saving that file writes it back into the Org file and saves it: ~ctrl-x n s~
- [ ] Widening in the narrowed file writes it back and closes it (~C-c '~ there does the same): ~ctrl-x n w~
- [ ] Zed's own folds open and close on headlines, drawers and blocks

* Headings and structure

*Partly:* A command on a selection acts on the cursor's line: Zed tells a server no selection. The commands go through the keys of keymap.json (Zed's tasks); for cloning, the answer is typed as a rename at the cursor (~F2~), as Zed has no box of its own for typed text. Turning a line into a heading (~org.toggle.heading~) is left out: it has no key in keymap.json and is not among the code actions. ~C-a~, ~C-e~, ~C-k~ and ~C-y~ keep Zed's own meaning, and nothing pasted is folded: Zed lets no server fold.

- [ ] On a headline, a new heading of the same level goes below: ~alt-enter~
- [ ] A new TODO heading: ~alt-shift-enter~
- [ ] A new heading after the subtree, and a TODO one: ~ctrl-enter~, ~ctrl-shift-enter~
- [ ] Promoting and demoting a heading; its tags stay aligned: the code action /Promote the heading; outdent the item; move the table column left/, the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/
- [ ] Promoting and demoting a subtree: the code action /Promote the subtree; outdent the item with its children; delete the table column/, the code action /Demote the subtree; indent the item with its children; insert a table column/
- [ ] Moving a subtree up and down past its siblings: the code action /Move the subtree, the item or the table row up/, the code action /Move the subtree, the item or the table row down/
- [ ] Inserting an inline task gives 15 stars and an ~END~ line; demoting it changes both; the outline leaves it out, and folding it hides its text and its ~END~ line: ~ctrl-c ctrl-x t~, the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/
- [ ] Cutting a subtree and pasting it under another heading: its level fits there: ~ctrl-c ctrl-x ctrl-w~, ~ctrl-c ctrl-x ctrl-y~
- [ ] Copying a subtree and pasting it: ~ctrl-c ctrl-x alt-w~, ~ctrl-c ctrl-x ctrl-y~
- [ ] With ~org_allow_promoting_top_level_subtree~ on, promoting ~* A~ makes it ~# A~: the code action /Promote the heading; outdent the item; move the table column left/
- [ ] Sorting the children of a heading alphabetically, then by TODO state: ~ctrl-c ^~
- [ ] Moving to the next and previous heading; with a count, that many: ~ctrl-c ctrl-n~, ~ctrl-c ctrl-p~
- [ ] Moving to the next and previous heading of the same level, stopping at the parent's end: ~ctrl-c ctrl-f~, ~ctrl-c ctrl-b~
- [ ] Moving to the parent heading; on a top heading Org says it is at the top level: ~ctrl-c ctrl-u~
- [ ] Going to a heading picked by its outline path (~A/B/~): ~ctrl-c ctrl-j~
- [ ] Toggling ~COMMENT~ on the heading (needs Emacs): ~ctrl-c ;~
- [ ] Cloning the subtree twice a week apart (~+1w~): the copies follow it with their dates moved (needs Emacs): ~ctrl-c ctrl-x c~
- [ ] The outline lists the headings nested, also in pickers that filter symbols by kind: the outline panel

Not in Zed:

- Off a table, turning a line into a heading and back (needs Emacs): /Turn the line into a heading, or the heading into a line/ is not among its keys or code actions

* Lists and checkboxes

*Partly:* ~RET~ stays Zed's own, and so do Shift and Alt with the arrows, which cycle bullets and move items in Org.

- [ ] On an item, the next item goes below; in a numbered list the numbers go on, after a checkbox item the new one has ~[ ]~: ~alt-enter~
- [ ] Indenting and outdenting an item; and with its children: the code action /Demote the heading; indent the item, the drawer or the block; move the table column right/, the code action /Promote the heading; outdent the item; move the table column left/, the code action /Demote the subtree; indent the item with its children; insert a table column/, the code action /Promote the subtree; outdent the item with its children; delete the table column/
- [ ] Moving an item up and down: the code action /Move the subtree, the item or the table row up/, the code action /Move the subtree, the item or the table row down/
- [ ] Toggling a checkbox: its parent box and the ~[1/3]~ cookie follow: ~ctrl-c ctrl-c~
- [ ] On a list numbered 1, 3, 2, the same command renumbers and repairs it: ~ctrl-c ctrl-c~
- [ ] Sorting a list's items alphabetically: ~ctrl-c ^~
- [ ] Off a table, turning lines into items and back (needs Emacs); in a table the same key inserts a rule below the row: ~ctrl-c -~

* TODO keywords

*Partly:* States are picked with buttons; for a note for a state change (~@~), the answer is typed as a rename at the cursor (~F2~), as Zed has no box of its own for typed text. Faces of particular keywords and priorities are not shown: Zed colors tokens by its theme only.

- [ ] With ~org_enforce_todo_dependencies~, a parent with a child not done cannot be done: the change is refused with ~blocked (by "TODO Child")~; with ~org_enforce_todo_checkbox_dependencies~, an entry with an unchecked box cannot either: ~ctrl-c ctrl-t~
- [ ] Those tasks are dimmed in the agenda and the TODO list
- [ ] Changing the TODO state of a headline (with ~org_todo_keywords~ keys, picked by key): ~ctrl-c ctrl-t~
- [ ] Cycling to the next and previous state: the code action /Cycle TODO state forward/, the code action /Cycle TODO state backward/
- [ ] Done with ~org_log_done = "time"~ writes ~CLOSED: [...]~ below the headline: ~ctrl-c ctrl-t~
- [ ] A state with ~@~ (~WAIT(w@)~) asks for a note, written below the headline: ~ctrl-c ctrl-t~
- [ ] Done on a repeating entry (~<2026-01-01 Thu +1w>~) moves its date a week on and keeps it TODO: ~ctrl-c ctrl-t~
- [ ] The parent's ~[1/2]~ cookie is recounted: ~ctrl-c ctrl-t~
- [ ] A ~#+TODO: A B | C~ line in the file is used instead of the settings: ~ctrl-c ctrl-t~
- [ ] With ~#+TODO: TODO | DONE~ and ~#+TODO: REPORT BUG | FIXED~, changing the state without keys goes ~BUG~, ~FIXED~, none, then back to ~REPORT~: ~ctrl-c ctrl-t~
- [ ] Switching to the next and previous keyword set says ~Keyword-Set 2/2: REPORT BUG FIXED~: ~ctrl-shift-right~, ~ctrl-shift-left~

* Priorities

- [ ] Raising and lowering the priority of a headline: the code action /Raise the priority/, the code action /Lower the priority/
- [ ] Setting it by key; ~SPC~ removes it: ~ctrl-c ,~
- [ ] ~#+PRIORITIES: 1 5 3~ makes the priorities numbers: the code action /Raise the priority/

* Tags

*Partly:* Tags are typed, not set with keys pressed in turn: the answer is typed as a rename at the cursor (~F2~), as Zed has no box of its own for typed text. Completion and renaming work. Faces of particular tags are not shown: Zed colors tokens by its theme only.

- [ ] Typing tags when none have keys; they are sorted and aligned to ~org_tags_column~: ~ctrl-c ctrl-q~
- [ ] Tags are completed after ~:~ at the end of a headline
- [ ] Renaming a tag renames it in every headline and ~#+FILETAGS:~: ~F2~ on the tag

* Properties and column view

*Partly:* A property, its value and the effort are typed, without completion: the answer is typed as a rename at the cursor (~F2~), as Zed has no box of its own for typed text. Column view is left out: it draws over the headlines. Custom properties are not hidden (~org.custom.properties.toggle~): Zed lets no server hide text. Deleting a property has no key in keymap.json and is not among the code actions; cycling a property's allowed values needs Shift with the arrows, which stay Zed's.

- [ ] Setting a property: the name and the value are asked for: ~ctrl-c ctrl-x p~
- [ ] Setting the effort: ~ctrl-c ctrl-x e~
- [ ] Toggling ~ORDERED~: ~ctrl-c ctrl-x o~
- [ ] Property names are completed in a drawer

Not in Zed:

- On a property line with ~NAME_ALL~, cycling through its values: /Move the date a day later, or cycle the TODO state or the list's bullets forward/, /Move the date a day earlier, or cycle the TODO state or the list's bullets backward/ are not among its keys or code actions
- Deleting a property from the entry, and from the whole file: /Delete a property of the entry/, /Delete a property from every entry of the file/ are not among its keys or code actions

* Dates and times

*Partly:* Dates are typed (~+2d~, ~fri 10:00~), with no calendar: the answer is typed as a rename at the cursor (~F2~), as Zed has no box of its own for typed text. Changing a timestamp works. Removing the scheduled date or the deadline is left out: those commands have no key in keymap.json and are not among the code actions.

- [ ] Scheduling with ~+2d~: ~SCHEDULED: <…>~ goes below the headline: ~ctrl-c ctrl-s~
- [ ] A deadline on ~fri 10:00~: ~ctrl-c ctrl-d~
- [ ] Inserting an active and an inactive timestamp; a second one right after makes a range: ~ctrl-c .~, ~ctrl-c !~
- [ ] On a timestamp, changing the day, month, year, hour and minute under the cursor; with a count: the code action /Increase the part of the timestamp at the cursor/, the code action /Decrease the part of the timestamp at the cursor/
- [ ] Moving a timestamp by days: the code action /Move the date one day later/, the code action /Move the date one day earlier/
- [ ] A repeater (~+1w~) and a warning (~-2d~) are kept as the date changes

Not in Zed:

- Removing the scheduled date and the deadline: /Remove the scheduled date of the entry/, /Remove the deadline of the entry/ are not among its keys or code actions

* Agenda

*Partly:* The agenda is a file, its commands keys through Zed's tasks (keymap.json), ~enter~ and ~tab~ going to an entry; adding today's appointments (~org.agenda.appt~) has no key and is not among the code actions; for a search and a date, the answer is typed as a rename at the cursor (~F2~), as Zed has no box of its own for typed text. Follow mode and the outline path of the cursor's entry are left out: Zed reports no cursor moves to an extension. Column view in the agenda is left out: it draws over the lines. The days of a habit's graph have Org's backgrounds for a dark background, a little transparent, with any theme: an extension's colors for tokens are the same with every theme.

- [ ] The agenda menu lists the views and the custom commands: ~ctrl-c a~
- [ ] The week view: scheduled entries, deadlines with their warnings, the time grid: the code action /Agenda for the current week or day/
- [ ] Later, earlier, today; day, week, month views; going to a date: ~f~, ~b~, ~.~, ~v d~, ~v w~, ~v m~, ~shift-j~
- [ ] With ~org_modules = ["org-habit"]~, a habit's consistency graph shows its days on the backgrounds of ~org-habit~'s faces: blue before it is due, green in its time to be done, yellow on the day it is due by, red past it, paler for the days the ~-future~ faces are for: the code action /Agenda for the current week or day/
- [ ] The TODO list, a tag search (~work+urgent~), a word search: ~ctrl-c a~
- [ ] With ~org_super_agenda_mode~ on and ~org_super_agenda_groups~ set (~[{ name = "Today", time-grid = true }, { auto-category = true }]~), each day of the agenda is in groups under their headers, and the TODO list too: the code action /Agenda for the current week or day/
- [ ] With ~org_agenda_prefix_format~ ~{ todo = " %-12:c%-4(org-entry-get nil "EFFORT") " }~, the TODO list shows each entry's effort after its category, ~nil~ without one (needs Emacs): the code action /List of all TODO entries/
- [ ] Going to the line's entry in another window, and where the agenda is: ~tab~, ~enter~
- [ ] Changing the line's TODO state and priority; the line follows: ~t~, ~+~ or ~shift-up~
- [ ] Scheduling the line's entry and setting its deadline: ~ctrl-c ctrl-s~, ~ctrl-c ctrl-d~
- [ ] Marking lines and a bulk action on them: ~m~, ~shift-b~
- [ ] Entry text, log mode, the clock report, archives mode: ~shift-e~ or ~v shift-e~, ~v l~, ~shift-r~ or ~v shift-r~, ~v a~
- [ ] In the week view, inactive timestamps show after ~[~ with /Display now includes inactive timestamps as well/, marked ~[~, and are gone again when the agenda is rebuilt: ~[~, ~v [~, ~r~
- [ ] Hovering a line shows its entry: the mouse
- [ ] Rebuilding the agenda, saving the changed files, quitting: ~r~, ~s~ or ~ctrl-x ctrl-s~
- [ ] An entry changed in its file shows in the agenda when it is rebuilt
- [ ] Pressing ~f~ many times in a row moves the agenda a week each time, in the editor too
- [ ] With no Org file open and no server running, the /Org: Agenda for the current week or day/ task opens the Org file last opened and the agenda
- [ ] Zed started again with the agenda's tab open shows the current week there, and its keys work
- [ ] ~ctrl-c a~ in an Org file asks for the agenda view with buttons; ~ctrl-c c~ captures

Not in Zed:

- Adding today's appointments: an entry timed a few minutes from now is reminded of every three minutes until it is due (needs Emacs): /Add today's appointments from the agenda files/ is not among its keys or code actions

* Clocking

*Partly:* No clock in the status line: Zed has no place there for an extension's text. In the agenda, the clocked entry's line has the background of ~org-agenda-clocking~ under its text, not to the window's edge: Zed lets no extension highlight a line, only give its tokens a background, and the tokens end with the text.

- [ ] Clocking into an entry whose effort its time passes shows ~Task ‘…’ should be finished by now. (0:30)~, once: ~ctrl-c ctrl-x ctrl-i~
- [ ] Clocking in: ~:LOGBOOK:~ gets a ~CLOCK:~ line and the clock shows (~[0:01] (Task)~): ~ctrl-c ctrl-x ctrl-i~
- [ ] Clocking out writes the end and the duration: ~ctrl-c ctrl-x ctrl-o~
- [ ] Cancelling the clock takes its line out: ~ctrl-c ctrl-x ctrl-q~
- [ ] Going to the clocked entry from another file: ~ctrl-c ctrl-x ctrl-j~
- [ ] Clocking in the last entry again: ~ctrl-c ctrl-x ctrl-x~
- [ ] The time clocked under each headline shows next to it: ~ctrl-c ctrl-x ctrl-d~
- [ ] A clock table: inserted, then updated; shifting its ~:block~ on the ~#+BEGIN:~ line: ~ctrl-c ctrl-x ctrl-r~, ~ctrl-c ctrl-x ctrl-u~
- [ ] A clock left running when the editor closed is asked about (~Dangling clock started N mins ago [jkKtTgGSscCiq]? ~); ~K~ and Enter stops it now: ~ctrl-c ctrl-x ctrl-z~
- [ ] With a clock left running and none clocked, clocking into another entry asks about it first: ~ctrl-c ctrl-x ctrl-i~
- [ ] In the agenda, clocking in and out; the clocked line's text is highlighted: ~shift-i~, ~shift-o~

* Capture

* Notes (org-roam)

*Partly:* A node's title is typed, without completion: the answer is typed as a rename at the cursor (~F2~), as Zed has no box of its own for typed text. The org-roam buffer does not follow the cursor: Zed reports no cursor moves to an extension. The commands without a key of Org's (a random node, aliases, tags, the buffer of a node and refreshing it) are left out: Zed runs a server's commands only from the keys of keymap.json and the code actions, and those are not among them.

- [ ] With ~org_roam_enabled~ on and ~org_roam_directory~ set, finding a node offers the titles and aliases of its files and visits the one picked: ~ctrl-c n f~
- [ ] Inserting a node puts ~[[id:…][title]]~ at the cursor; on a selection, the selection is typed first and the link takes its place: ~ctrl-c n i~
- [ ] A title no node has opens a capture buffer with the new file's ~ID~ and ~#+title:~; finishing writes the file and, from insert, puts the link in: ~ctrl-c n i~
- [ ] Following ~[[roam:Title]]~ visits the node and turns the link into ~[[id:…][Title]]~; saving does it for the others: ~ctrl-c ctrl-o~
- [ ] Typing ~[[roam:~ or ~[[id:~ offers the titles of the nodes; the one picked becomes an ~id:~ link
- [ ] Toggling the org-roam buffer in a node another links to shows it beside, the cursor staying in the note, with /Backlinks (1)/ and the linking node's heading and text; toggling again hides it: ~ctrl-c n l~
- [ ] Following an item of the buffer visits the line of the link: ~ctrl-c ctrl-o~
- [ ] Going to today's daily note makes ~daily/YYYY-MM-DD.org~ with its ~ID~ and ~#+title:~; capturing to it adds an entry at its end; the next and previous notes go from one to the other: ~ctrl-c n d d~, ~ctrl-c n d n~, ~ctrl-c n d f~
- [ ] Opening the directory of the daily notes offers its notes; the one picked is visited: ~ctrl-c n d .~

Not in Zed:

- Adding tags to a file's node writes ~#+filetags:~; on a headline's node, its tags: /Roam: add tags/ is not among its keys or code actions
- A dedicated buffer for a node asked for opens in a file of its own and stays on that node: /Roam: show the org-roam buffer of a node/ is not among its keys or code actions
