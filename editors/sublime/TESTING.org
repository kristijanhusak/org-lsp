What to try in Sublime Text to know that everything org-lsp does works
there. The keys are the defaults. Tick a box once it works; a check that
fails is a bug to report. [[file:../../docs/sublime.org][docs/sublime.org]] says what is left out
here and why.

To look at most of what a file shows at once (highlighting, concealing,
entities, folding when it opens, indentation, shrunk columns,
diagnostics), open [[file:../../tests/visual.org][tests/visual.org]]: each of
its sections says what it should look like.

* Setup

- [ ] Installed with ~install.sh sublime~: LSP comes with it, and the server in =~/.local/bin= starts on an Org file
- [ ] LSP's ~semantic_highlighting~ is on
- [ ] LSP's ~show_inlay_hints~ is on: the time clocked and the ~…~ of shrunk columns come as inlay hints
- [ ] The ~Org:~ commands are in the Command Palette; /Org: Download the latest server/ replaces the downloaded server

* Highlighting

*Partly:* Links, emphasis markers, pretty entities and sub- and superscripts are not concealed: Sublime Text cannot hide text in a view. The colors need LSP's ~semantic_highlighting~ on.

- [ ] Headlines are colored by level; TODO and DONE keywords, priorities (~[#A]~) and tags have colors of their own
- [ ] ~*bold*~, ~/italic/~, ~_underline_~, ~+strike+~, ~=verbatim=~ and =~code~= are colored
- [ ] Timestamps, ~SCHEDULED:~ and ~DEADLINE:~, ~CLOCK:~ lines, drawers, ~#+~ keywords and ~#~ comments are colored
- [ ] A ~#+begin_src python~ block shows its code in Python's colors
- [ ] Inline code (~src_python{x = 1}~) is in Python's colors
- [ ] Table rules and bars, footnotes (~[fn:1]~), ~<<targets>>~, macros (~{{{x}}}~) and entities (~\alpha~) are colored
- [ ] A subtree tagged ~:ARCHIVE:~ is shaded

* Folding and visibility

- [ ] On a headline, cycling goes folded → children → subtree: ~Tab~
- [ ] Cycling the whole file goes overview → contents → everything: ~Shift+Tab~
- [ ] A file with ~#+STARTUP: overview~ opens folded; with ~content~ its headlines show, those without children folded, and its drawers folded
- [ ] A subtree with ~:VISIBILITY: children~ opens with its children folded, one with ~all~ open
- [ ] Two blank lines after a subtree stay visible below it when it is folded
- [ ] Narrowing to the subtree opens it in a file of its own; saving that file writes it back into the Org file and saves it: ~Ctrl+X n s~
- [ ] Widening in the narrowed file writes it back and closes it (~C-c '~ there does the same): ~Ctrl+X n w~
- [ ] Opening the parent of an ~:ARCHIVE:~ subtree leaves that subtree folded
- [ ] A sparse tree of the TODO entries folds everything else and highlights them: ~Ctrl+C /~
- [ ] With everything folded, showing the context of a line deep in a subtree opens the headlines above it and leaves the other subtrees folded: ~Ctrl+C Ctrl+R~

- [ ] With ~org_enforce_todo_dependencies~, a parent with a child not done cannot be done: the change is refused with ~blocked (by "TODO Child")~; with ~org_enforce_todo_checkbox_dependencies~, an entry with an unchecked box cannot either: ~Ctrl+C Ctrl+T~

- [ ] Cycling to the next and previous state: /Org: Cycle TODO state forward/, /Org: Cycle TODO state backward/

- [ ] A state with ~@~ (~WAIT(w@)~) asks for a note, written below the headline: ~Ctrl+C Ctrl+T~

- [ ] With ~#+TODO: TODO | DONE~ and ~#+TODO: REPORT BUG | FIXED~, changing the state without keys goes ~BUG~, ~FIXED~, none, then back to ~REPORT~: ~Ctrl+C Ctrl+T~
