#+title: Org in Zed
#+options: ^:{} toc:nil

~editors/zed~ is a Zed extension that runs Org through the server. Zed lets
an extension do less than the other editors do, so the commands come as
code actions, what they ask for is asked with buttons, and the agenda's
keys go through Zed's tasks.

* Installing

Install /Org (org-lsp)/ from Zed's extensions (*zed: extensions*), once
it is in Zed's registry. A Zed extension cannot bring keys or tasks of its
own, so add those afterwards: the [[file:keys/zed.org::#keys-through-tasks][keys through tasks]] are the release's
~org-lsp-zed-keymap.json~ and ~org-lsp-zed-tasks.json~, whose entries go at
the start of the arrays in your ~keymap.json~ and ~tasks.json~ (in
=~/.config/zed=, or ~%APPDATA%\Zed~ on Windows). ~install.sh zed~, below,
adds them for you.

The script installs everything at once:

#+begin_src sh
curl -fsSL https://github.com/kristijanhusak/org-lsp/releases/download/nightly/install.sh | bash -s -- zed
#+end_src

or, in a checkout of this repository, ~scripts/install.sh zed~
(~--release v0.2.0~ for a release, ~--source~ for the server built from
the checkout). It puts in place what Zed's extension registry would, from
the [[https://github.com/kristijanhusak/org-lsp/releases/tag/nightly][nightly release]]:

- the extension, built, in Zed's ~extensions/installed/org-lsp~;
- the server beside it, in ~extensions/work/org-lsp~, where the extension
  looks first;
- the tasks and keys of [[file:keys/zed.org::#keys-through-tasks][keys through tasks]], added to the start of your
  ~tasks.json~ and ~keymap.json~ between two ~// BEGIN org-lsp~ and
  ~// END org-lsp~ comments, which it replaces when run again. Your own
  keys come after them, and win.

Restart Zed afterwards; run the script again to update.

Without the script, the extension starts ~org-lsp~ from your PATH, or else
downloads the server of its own release for your platform once (~v0.2.0~
for version 0.2.0 of the extension, the nightly build for the nightly
one), which needs the repository to be public; ~lsp.org-lsp.binary.path~
names a server binary of your own. To work on the extension, run *zed:
install dev extension* and pick ~editors/zed~ of a checkout (Zed builds it
with Rust).

* Setting it up

The settings go in Zed's settings (*zed: open settings*). Zed asks the
server for its colors only with ~semantic_tokens~, and shows indentation,
pretty entities and the clock's times as inlay hints. The server's options
go in ~initialization_options~:

#+begin_src json
{
  "languages": {
    "Org": { "semantic_tokens": "combined", "inlay_hints": { "enabled": true } }
  },
  "lsp": {
    "org-lsp": {
      "initialization_options": {
        "org_agenda_files": ["~/org"],
        "org_todo_keywords": ["TODO(t)", "NEXT(n)", "|", "DONE(d!)"],
        "org_capture_templates": [
          { "key": "t", "description": "Task", "target": ["file+headline", "~/org/inbox.org", "Tasks"], "template": "* TODO %?\n  %U" }
        ],
        "org_agenda_custom_commands": [
          { "key": "n", "description": "Next actions", "type": "todo", "match": "NEXT" }
        ]
      }
    }
  }
}
#+end_src

The server also reads [[file:configuration.org::#the-shared-configuration-file][the shared configuration file]],
=~/.config/org-lsp/config.toml=, which every editor shares;
~initialization_options~ goes on top of it. [[file:configuration.org][configuration.org]] has everything
else: [[file:configuration.org::#zed][Zed's settings for Org]] and [[file:configuration.org::#every-option-at-its-default][every option of the server]] with its
default.

* Using it

In Org files the commands are in the code actions (*editor: toggle code
actions*, ~ctrl-.~ or ~cmd-.~), which list what applies where the cursor is.
What a command asks for is asked with buttons: a TODO state, a priority, a
refile target, a capture template, yes or no. Zed has no box of its own
for a server to ask for typed text, so a command that wants a date or text
says /PROMPT: answer with a rename at the cursor/: rename at the cursor
(~F2~) and type the answer for the new name, or ~-~ alone for an empty
answer (the prompt's default), as Zed sends no empty new name.

Org's keys, and the agenda's, run the commands once two files of the
extension are pasted into your tasks and keymap. The agenda, the TODO
list, the agenda menu and capture then need no Org file open: run them
from the task picker (*task: spawn*; type ~Org:~). [[file:keys/zed.org][keys/zed.org]] says how,
and lists the keys.

* Developing

~node editors/zed/generate.mjs~ writes the semantic token rules
(~languages/org/semantic_token_rules.json~), ~tasks.json~ and ~keymap.json~
from the server's manifest; ~--check~ fails if they are out of date.
~cargo build --target wasm32-wasip2~ in ~editors/zed~ builds the extension.
~editors/zed/test/run.py~ runs the shared end-to-end scenarios in Zed,
pressing its keys ([[file:development.org::#end-to-end-scenarios][end-to-end scenarios]]).
