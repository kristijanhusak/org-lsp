#+title: Keys in VS Code
#+options: ^:{} toc:nil

The setting ~org-lsp.keys~ picks which keys the extension binds:

- ~"emacs"~ (the default): Emacs's keys, in Org files (~Ctrl+C Ctrl+T~, ~Tab~,
  ~Shift~ and the arrows …), in capture buffers, and Org's single letters in
  the agenda and the date prompt, which are read-only. In Org files ~Ctrl+C~
  then waits for a second key instead of copying; ~Ctrl+Insert~ and the
  context menu still copy.
- ~"vim"~: the Neovim plugin's keys, for VSCodeVim. In Org files, VS Code
  binds only the keys that take nothing from Vim (~Tab~, ~Shift+Tab~,
  ~Ctrl+Space~, ~Ctrl+A~, ~Ctrl+X~, ~Shift+Up~, ~Shift+Down~), in Normal mode;
  the keys with the leader go in VSCodeVim's own settings, below. Keys such
  as ~cit~ would take ~c~ from Vim, so they are not bound.
- ~"custom"~: no keys at all. Bind the commands yourself, as [[#changing-them][below]].

~Tab~ and ~Shift+Tab~ cycle the visibility of a subtree and of the whole file,
as Org's ~TAB~ and ~S-TAB~ do: folded, its children, all of it; the top
level, every headline, everything. Off a headline, block or drawer, ~Tab~ is
VS Code's own. The commands are also in the Command Palette under *Org*,
and the ones that change the text at the cursor under *Quick Fix…*
(~Ctrl+.~). *Org: Show the keys* lists the keys of the editor at hand.

The bindings are written into ~package.json~ from the server's own
description of its commands. *Preferences: Open Keyboard Shortcuts* lists
them; search for ~org.~. [[file:../vscode.org][vscode.org]] says how to install and set up the
extension.

* How they behave

Questions are asked in VS Code's own way:

- *A date* (scheduling, a deadline, ~Shift+J~ in the agenda) opens Emacs's
  calendar beside the file, with the keys under /In the date prompt/. ~i~
  there asks for the date in an input box, with the timestamp the answer
  makes shown as you type. ~t~ picks a time: a ~Time:~ line shows it,
  ~Shift+Left~ and ~Shift+Right~ choose the hour or the minutes, ~Shift+Up~
  and ~Shift+Down~ move it up or down (the minutes by
  ~org_time_stamp_rounding_minutes~), and ~t~ again goes back to the days,
  keeping the time.
- *One key*, such as a TODO keyword with a key or a capture template, is
  picked from a list that shows each choice's key (~[t] TODO~). Type the
  key (or its name, as ~SPC~) and press ~Enter~; other text narrows the
  list.
- *A choice from a list*, such as a refile target, is picked from a list.
- *Text*, such as a capture prompt, is typed in an input box. It starts
  with what Emacs's minibuffer starts with (a headline's tags, the time of
  a timestamp being changed), the cursor after it.
- *A state note* (a keyword with ~@~, as ~WAIT(w@)~) is written in a note
  buffer that opens like a capture buffer, as Emacs's =*Org Note*=:
  ~Ctrl+C Ctrl+C~ stores it, ~Ctrl+C Ctrl+K~ changes the state without it.

What Emacs says when a command is done (/Priority of current item set to
B/, /Scheduled to <2026-05-22 Fri>/) shows as a notification, or in the status
bar with ~"org-lsp.messages": "statusBar"~; a command that cannot run says
why in a warning.

VS Code passes no count to a key: each command moves by one step, unless
the key gives a count of its own (below).

* Changing them
:PROPERTIES:
:CUSTOM_ID: changing-them
:END:

Open *Preferences: Open Keyboard Shortcuts (JSON)* and add entries to
~keybindings.json~. Each binding needs a ~when~ clause that says where it
applies:

#+begin_src json
// Org files
"when": "editorTextFocus && editorLangId == 'org'"
// The agenda
"when": "editorTextFocus && editorLangId == 'org-agenda'"
// The date prompt
"when": "editorTextFocus && editorLangId == 'org-date'"
// A capture buffer
"when": "editorTextFocus && editorLangId == 'org' && resourceFilename =~ /^CAPTURE-/"
#+end_src

To add a key, bind it to the command's name, from the second column of the
tables above:

#+begin_src json
[
  { "key": "ctrl+alt+a", "command": "org.agenda.dispatch" },
  { "key": "ctrl+alt+c", "command": "org.capture" },
  { "key": "alt+t", "command": "org.todo", "when": "editorTextFocus && editorLangId == 'org'" },
  { "key": "alt+up", "command": "org.shift.up", "when": "editorTextFocus && editorLangId == 'org'" },
  { "key": "alt+down", "command": "org.shift.down", "when": "editorTextFocus && editorLangId == 'org'" },
  { "key": "alt+left", "command": "org.shift.left", "when": "editorTextFocus && editorLangId == 'org'" },
  { "key": "alt+right", "command": "org.shift.right", "when": "editorTextFocus && editorLangId == 'org'" },
  { "key": "alt+s", "command": "org.schedule", "when": "editorTextFocus && editorLangId == 'org'" }
]
#+end_src

The first two have no ~when~, so they work anywhere, as Emacs's ~C-c a~ and
~C-c c~ do. With ~"org-lsp.keys": "custom"~ these are the only keys there
are.

~"args": { "count": N }~ passes Emacs's prefix argument: ~C-u~ is 4,
~C-u C-u~ 16, ~C-u C-u C-u~ 64. For example, the images of the whole file,
and none:

#+begin_src json
[
  { "key": "ctrl+c ctrl+x v", "command": "org.link.preview", "args": { "count": 16 }, "when": "editorTextFocus && editorLangId == 'org'" },
  { "key": "ctrl+c ctrl+x shift+v", "command": "org.link.preview", "args": { "count": 64 }, "when": "editorTextFocus && editorLangId == 'org'" }
]
#+end_src

To remove a default key, add the same key and command with a ~-~ in front
of the command. To change one, remove it and add the new key:

#+begin_src json
[
  { "key": "shift+j", "command": "-org.agenda.goto.date" },
  { "key": "ctrl+j", "command": "org.agenda.goto.date", "when": "editorTextFocus && editorLangId == 'org-agenda'" }
]
#+end_src

The same can be done in *Preferences: Open Keyboard Shortcuts*: search for
~org.~, then right-click a binding to change or remove it.
