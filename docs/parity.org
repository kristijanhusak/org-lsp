- Helix ❌: Helix does not use semantic tokens: it colors Org with its own tree-sitter grammar.

- ✅ Sparse trees (~C-c /~), their matches in archived subtrees left folded unless ~org-sparse-tree-open-archived-trees~
- ✅ Narrowing to a subtree or block (~C-x n s~, ~C-x n b~) and the subtree in an indirect buffer (~C-c C-x b~): it in a file of its own, all there is to see there, written back each time it is saved
- ✅ Showing the context of the cursor (~org-reveal~, ~C-c C-r~): its entry, the next headline, its siblings and its ancestors, the other folds left as they are; ~org.reveal.siblings~ (~C-u~) each level with its children, ~org.reveal.tree~ (~C-u C-u~) the parent's whole tree
- ✅ ~TAB~ on a new, empty headline or item changing its level (~org-cycle-level-after-item/entry-creation~), and at the start of the file cycling the file (~org-cycle-global-at-bob~); list items folding, as part of the outline or not at all (~org-cycle-include-plain-lists~); headlines folding to a level (~org-cycle-max-level~)
- ❌ The other options of cycling (~org-cycle-emulate-tab~, ~org-show-context-detail~, ~org-fold-catch-invisible-edits~)

Where editors fall short:

- Neovim ❓: Cycling the whole file goes between overview and everything: it has no contents state, which needs folds of a headline's own text that Neovim's fold levels do not make. ~<Tab>~ changes the level of a new entry in Normal mode; in Insert mode it is a tab.
- Vim ❓: Cycling the whole file goes between overview and everything: it has no contents state, which needs folds of a headline's own text that Vim's fold levels do not make. A closed fold's line is not highlighted: Vim draws it in one color. ~<Tab>~ changes the level of a new entry in Normal mode; in Insert mode it is a tab.
- VS Code ❓: A closed fold ends in VS Code's own ~⋯~: an extension cannot change it (~org_ellipsis~).
- Sublime Text ❓: A closed fold ends in Sublime Text's own marker: a package cannot change it (~org_ellipsis~).
- Zed ❓: Zed folds with its own folding: Org's cycling and sparse trees need folds an extension can set, which Zed does not offer.
- Helix ❌: Helix has no folding.

** Done another way

- ~org-agenda-skip-timestamp-if-deadline-is-shown~ :: no effect in Org 9.8.10: ~org-agenda-get-timestamps~ looks the entry up with ~assq~ in a list of positions, which finds none; none here either

- ~org-cycle-level-after-item/entry-creation~ :: the setting ~org_cycle_level_after_item_entry_creation~, its name without the ~/~
- ~org-id-locations-file-relative~ :: org-lsp reads the locations file and never writes it; names in it that are not absolute are relative to its directory, as Emacs reads them
- ~org-tab-follows-link~ :: TAB is the editor's key for folding and tables; a link is followed with org.open (C-c C-o), go to definition, or RET with org_return_follows_link
- ~org-table-auto-blank-field~ :: the editor types into a field as into any text: TAB leaves the cursor at the start of the field's text, as in Emacs, and the first character typed does not blank it
- ~org-table-formula-use-constants~ :: only for a formula evaluated on its own (~C-c =~, a field starting with ~=~), which org-lsp does not do; the formulas of ~#+TBLFM:~ lines always use the constants, in Emacs too
