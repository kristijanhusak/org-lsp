#+title: Configuring org-lsp
#+options: ^:{} toc:2

Everything that can be set, in one place: the server's options, which are
the same in every editor, and each editor's own settings. The page of each
editor ([[file:neovim.org][Neovim]], [[file:vim.org][Vim]], [[file:vscode.org][VS Code]], [[file:sublime.org][Sublime Text]], [[file:zed.org][Zed]], [[file:helix.org][Helix]]) shows a
short example in its own syntax and points here for the rest.

Nothing has to be set. Without configuration the agenda is built from the
Org files of the workspace (or the ones that are open), and every option
is Org's default.

* The server's options
:PROPERTIES:
:CUSTOM_ID: the-servers-options
:END:

The server's options are Org's variables: TODO keywords, agenda files,
capture templates, logging and the rest. They come from three places, each
over the one before:

1. Org's defaults;
2. the [[#the-shared-configuration-file][shared configuration file]], which the server reads itself;
3. the options the editor passes when it starts the server (Neovim's
   ~settings~, VS Code's ~org-lsp.settings~, Helix's ~config~ …).

So the options can be set once, in the shared file, for every editor, and
an editor can still change any of them for itself. A file's own ~#+TODO:~
and ~#+PRIORITIES:~ lines apply to that file, over all three.

** Names

An option is named after the Org variable it stands for, with =_= for =-=:
~org-agenda-files~ is ~org_agenda_files~, ~org-log-done~ is ~org_log_done~.
Org's own spelling, ~org-agenda-files~, works as well (TOML and JSON allow
it; in Lua it needs ~['org-agenda-files']~). The values are Org's, written
as JSON: ='time= is ~"time"~, ~nil~ is ~false~, a list is a list.

Options the server has and Org does not have plain names without ~org_~
(~auto_save~, ~config_file~, ~emacs_config~). The keys inside an option
are the keywords Org uses there, as a refile target's ~maxlevel~ and a
capture template's ~empty_lines~ (~:empty-lines~).

The names options had before (~agendaFiles~, ~agenda.span~ …) still work;
the server says which to use instead.

** The shared configuration file
:PROPERTIES:
:CUSTOM_ID: the-shared-configuration-file
:END:

The server reads the first of these that is there:

1. the file the editor names with the ~config_file~ option (see
   [[#leaving-the-file-out-or-using-another][below]]);
2. the file named by =$ORG_LSP_CONFIG=;
3. ~config.toml~ or ~config.json~ in =$XDG_CONFIG_HOME/org-lsp=;
4. ~config.toml~ or ~config.json~ in =~/.config/org-lsp= (on Windows,
   =%APPDATA%\org-lsp=).

Write it in [[https://toml.io][TOML]] or in JSON, whichever you prefer. With both there, the
server reads ~config.toml~ and says that it leaves ~config.json~ out. A file
named by ~config_file~ or =$ORG_LSP_CONFIG= is JSON if its name ends in
~.json~, and TOML otherwise.

In TOML:

#+begin_src toml
org_agenda_files = ["~/org"]
org_todo_keywords = ["TODO(t)", "NEXT(n)", "WAIT(w@/!)", "|", "DONE(d!)", "CANCELLED(c@)"]
org_log_done = "time"
org_log_into_drawer = true
org_refile_targets = [{ files = "agenda", maxlevel = 2 }]
org_agenda_span = "day"
org_agenda_start_on_weekday = 0

[[org_capture_templates]]
key = "t"
description = "Task"
target = ["file+headline", "~/org/inbox.org", "Tasks"]
template = "* TODO %?\n  %U"

[[org_capture_templates]]
key = "n"
description = "Note"
target = ["file", "~/org/notes.org"]
template = ["* %^{Title}", "%U", "", "%?"]
#+end_src

The same in JSON, which may have comments and trailing commas, as VS
Code's ~settings.json~ does, so that options can be copied from there as
they are:

#+begin_src json
{
  "org_agenda_files": ["~/org"],
  "org_todo_keywords": ["TODO(t)", "NEXT(n)", "WAIT(w@/!)", "|", "DONE(d!)", "CANCELLED(c@)"],
  "org_log_done": "time",
  "org_log_into_drawer": true,
  "org_refile_targets": [{ "files": "agenda", "maxlevel": 2 }],
  "org_agenda_span": "day",
  "org_agenda_start_on_weekday": 0,
  "org_capture_templates": [
    { "key": "t", "description": "Task", "target": ["file+headline", "~/org/inbox.org", "Tasks"], "template": "* TODO %?\n  %U" },
    // Notes, in a file of their own.
    { "key": "n", "description": "Note", "target": ["file", "~/org/notes.org"], "template": ["* %^{Title}", "%U", "", "%?"] },
  ],
}
#+end_src

TOML is easier to write by hand: templates can go over several lines, and
there are no braces to balance. JSON is easier to copy settings into from
VS Code. [[#every-option-at-its-default][The end of this page]] has every option, each under its own
heading, with its default; [[file:config.toml][config.toml]] is the whole file with every option at
its default and what it means, to copy and change.

~org-lsp config~ shows which file the server reads, anything wrong with
it, and the options it comes to; with ~--options~, it puts an editor's
options on top, as the server would
(~org-lsp config --options '{"org_agenda_span": "day"}'~):

#+begin_example
$ org-lsp config
Configuration file: /home/me/.config/org-lsp/config.toml
Options:
{
  "org_agenda_files": [
    "~/org"
  ],
  "org_log_done": "time"
}
#+end_example

*** Completion and checking

[[file:config.schema.json][config.schema.json]] is the JSON Schema of the file, written from the
server's own table of options. An editor that knows JSON Schema completes
and checks the options with it, and flags a misspelt name. In JSON, name
it with ~$schema~:

#+begin_src json
{
  "$schema": "https://raw.githubusercontent.com/kristijanhusak/org-lsp/main/docs/config.schema.json",
  "org_log_done": "time"
}
#+end_src

In TOML, editors that use [[https://taplo.tamasfe.dev][Taplo]] (VS Code's Even Better TOML, Helix,
Neovim's ~taplo~ server) read a ~#:schema~ comment at the top of the file:

#+begin_src toml
#:schema https://raw.githubusercontent.com/kristijanhusak/org-lsp/main/docs/config.schema.json
org_log_done = "time"
#+end_src

The editors check the options they pass too: the Neovim plugin's options
have types for lua-language-server, and VS Code completes and checks
~org-lsp.settings~ (see their sections below).

** An editor's options on top

An editor's options go on top of the file's:

- an option the editor sets replaces the file's;
- an object, such as ~org_agenda_prefix_format~ or ~emacs_options~, is
  merged key by key, the value of each key it has replacing the file's
  whole;
- a list, such as ~org_capture_templates~ or ~org_agenda_files~, is
  replaced whole.

With the file above, this Neovim configuration shows a week in the agenda,
and keeps everything else from the file:

#+begin_src lua
require('org-lsp').setup({ settings = { org_agenda_span = 'week' } })
#+end_src

A list replaces the default list whole too: with ~org_capture_templates~
set, its templates are the only ones, and Org's default one is gone.

** Leaving the file out, or using another
:PROPERTIES:
:CUSTOM_ID: leaving-the-file-out-or-using-another
:END:

~config_file~ is an option only an editor gives. It says which file to
read:

- ~false~: none; the editor's options alone count;
- a path: that file instead (=~/= is the home directory). It must exist:
  the server says so when it cannot read it.

#+begin_src lua
-- Neovim: no shared file.
require('org-lsp').setup({ settings = { config_file = false } })
#+end_src

#+begin_src json
// VS Code: the work configuration.
{ "org-lsp.settings": { "config_file": "~/work/org-lsp.toml" } }
#+end_src

** Custom agenda commands
:PROPERTIES:
:CUSTOM_ID: custom-agenda-commands
:END:

~org_agenda_custom_commands~ is Emacs's ~org-agenda-custom-commands~: views
of your own in the agenda menu (~C-c a~, ~<Leader>oa~), next to ~a~ (the
agenda), ~t~ (the TODO list) and ~m~ or ~M~ (a tags search, asked for). A
command is one view, or a block agenda: several views one after the other,
with a line of ~=~ between them.

#+begin_src toml
[[org_agenda_custom_commands]]
key = "n"
description = "Next actions"
type = "todo"
match = "NEXT|WAIT"

[[org_agenda_custom_commands]]
key = "w"
description = "Work, open"
type = "tags-todo"
match = "work-email"

# A prefix key: the menu then offers the commands under it.
[[org_agenda_custom_commands]]
key = "d"
description = "Daily"

[[org_agenda_custom_commands]]
key = "dd"
description = "Today, then what is waiting"
blocks = [
  { type = "agenda", settings = { org_agenda_span = "day" } },
  { type = "tags-todo", match = "PRIORITY=\"A\"", header = "Urgent" },
  { type = "todo", match = "WAIT", header = "Waiting for" },
]

# Tomorrow's deadlines, the earliest first.
[[org_agenda_custom_commands]]
key = "D"
description = "Due tomorrow"
type = "tags-todo"
match = "DEADLINE>=\"<+1d>\"&DEADLINE<\"<+2d>\""
settings = { org_agenda_sorting_strategy = ["deadline-up", "urgency-down"] }

# Open TODO entries the agenda does not show yet: nothing scheduled, no
# deadline in its warning period.
[[org_agenda_custom_commands]]
key = "u"
description = "Not planned"
type = "alltodo"
settings = { org_agenda_todo_ignore_scheduled = "all", org_agenda_todo_ignore_deadlines = "near" }
#+end_src

The views:

| ~type~      | Shows                            | ~match~     |
|-------------+----------------------------------+-------------|
| ~agenda~    | the day or week agenda           |             |
| ~alltodo~   | every open TODO entry            |             |
| ~todo~      | entries with these keywords      | ~NEXT¦WAIT~ |
| ~tags~      | entries the match string matches | ~work-home~ |
| ~tags-todo~ | the same, open TODO entries only | ~work-home~ |
| ~search~    | entries with these words         | ~meeting~   |
| ~stuck~     | stuck projects                   |             |

(In the table, =¦= stands for =|=, which an Org table cannot hold.)

A match string is Org's: tags joined with ~+~ (and), ~-~ (not) and =|=
(or), as in =work+urgent-home|@phone=; a regexp in braces, ~{^proj}~;
properties, as in ~OWNER="alice"~, ~EFFORT>2~, ~PRIORITY="A"~, ~LEVEL>1~,
~TODO="NEXT"~, ~SCHEDULED<"<today>"~ (a ~*~ after the operator, as in
~EFFORT<*3~, also requires the property); and, after a slash, keywords:
=work/NEXT|WAIT=, or ~work/!~ for any open one.

~header~ replaces a view's header, and an empty one leaves it out.
~settings~ holds agenda options for a command or a block, as Org's
settings list does: ~org_agenda_span~, ~org_agenda_start_day~ (~-1d~,
~2026-10-01~), ~org_deadline_warning_days~, ~org_agenda_use_time_grid~,
~org_agenda_sorting_strategy~ (one list, for the block's kind of view),
~org_agenda_max_entries~ and the others. A block's settings go over its
command's, which go over the options'.

In a block agenda, ~f~, ~b~, ~.~, ~j~ and the span keys move the agenda
block the cursor is in, as in Emacs.

:CUSTOM_ID: plugins

org-super-agenda, org-roam and org-journal, Emacs packages built on Org,

** org-protocol URLs
:PROPERTIES:
:CUSTOM_ID: org-protocol-urls
:END:

Bookmarklets that store a link to a page or capture it, and links that
open a page's source, reach org-lsp through ~org-lsp protocol URL~:
[[file:org-protocol.org][org-protocol.org]] says how to set it up. Its options are Org's
([[#org-protocol][below]]): ~org_protocol_default_template_key~, the template of a capture
whose URL names none; ~org_protocol_data_separator~, for old-style URLs;
~org_protocol_project_alist~, where the files of published pages are, for
~open-source~; and org-lsp's own ~org_protocol_editor~, the editor to start
when none runs, which only the shared file can give, as no editor runs
then:

#+begin_src toml
org_protocol_default_template_key = "w"
org_protocol_editor = "code"

[[org_protocol_project_alist]]
name = "Worg"
base_url = "https://orgmode.org/worg/"
working_directory = "~/org/worg/"
online_suffix = ".html"
working_suffix = ".org"
#+end_src

** Export, Babel and other work in Emacs
:PROPERTIES:
:CUSTOM_ID: export-babel-and-other-work-in-emacs
:END:

What only Emacs can do, the server has Emacs do, when Emacs (with Org 9.6
or newer) is installed: export (~C-c C-e~, ~<Leader>oe~ in Vim and Neovim),
evaluating code blocks (~C-c C-c~ on a block, ~C-c C-v b~ for the file's),
LaTeX previews, encryption and a few others. The server starts Emacs the
first time and keeps it running. Moving rows in column view
(~org-columns-move-row-up~, ~M-<up>~) needs a newer Org than the 9.6.15
that Emacs 29 comes with.

Org's options for these go in ~emacs_options~, by their names in Org, with
values as the other options have them: ~true~ is ~t~, ~false~ is ~nil~, a
string is a symbol where the option takes one (~"mv"~ is ~mv~), and a table
is an association list.

#+begin_src toml
# ~/.config/org-lsp/config.toml
[emacs_options]
org-attach-method = "mv"
org-attach-id-dir = "~/org/data/"
org-export-with-toc = false
org-export-backends = ["ascii", "html", "icalendar", "latex", "md", "odt"]
org-babel-load-languages = { emacs-lisp = true, python = true }
#+end_src

Emacs sets each, as Customize would, when it loads the library the option
is in (~org-attach~ for ~org-attach-method~), and checks it against the
option's type: a value the option does not take is left out, with a
message saying what it takes. The options are those Emacs reads:
[[file:emacs-options.org][emacs-options.org]] lists each, with Org's documentation of it, its default
and its type. For the others the server says why it leaves them out: most
are settings of the server, and a function or a hook is Lisp.

Lisp goes in a file Emacs loads before Org, or inline. Emacs loads
~emacs_config_file~, then evaluates ~emacs_config~, then sets
~emacs_options~, which so win over both:

#+begin_src toml
# ~/.config/org-lsp/config.toml
emacs_config_file = "~/.config/org-lsp/export.el"
emacs_config = '''
(add-to-list 'load-path "~/src/org-mode/lisp")
(setq org-html-format-drawer-function #'my-drawer)
(add-hook 'org-export-before-processing-functions #'my-before-export)
'''
#+end_src

Emacs asks before it evaluates code, and the editor shows the question.

** When something is wrong
:PROPERTIES:
:CUSTOM_ID: when-something-is-wrong
:END:

The server never refuses to start because of its options:

- a file that is not valid TOML or JSON is left out whole, and the server
  shows a message naming the file and the line;
- an option with a value of the wrong type is left out on its own, with a
  message; the other options apply;
- an option the server does not know is named in a message, which catches
  a misspelt name.

The messages also go to the editor's LSP log (~:checkhealth vim.lsp~ in
Neovim shows where it is; the *Output* panel's *Org Language Server* in VS
Code; ~:log-open~ in Helix).

The server reads its options when it starts. After changing them, restart
it: ~:lsp restart~ in Neovim 0.12, *Org: Restart Language Server* in VS
Code (which restarts it by itself when ~org-lsp.settings~ changes),
~:lsp-restart~ in Helix, *LSP: Restart Servers* in Sublime Text.

* Each editor's own settings

Besides passing the server's options, each editor has settings of its own:
where the server comes from, the keys, how windows open, what is shown.

** Neovim
:PROPERTIES:
:CUSTOM_ID: neovim
:END:

Set ~vim.g.org_lsp~ before the plugin loads (before ~vim.pack.add()~, or
in lazy.nvim's ~init~), or call ~require('org-lsp').setup()~ at any time; calling it more
than once merges each call into what was there. What you set is merged
into the defaults, so you only write what you want to change. These are
the defaults:

#+begin_src lua
require('org-lsp').setup({
  -- The server command. Unset, the plugin uses the server it built
  -- (target/release/org-lsp in the plugin's directory), `org-lsp` from
  -- PATH, or the one it downloaded.
  cmd = nil,

  -- When no server is found, download the build of `release` for this
  -- platform into stdpath('data')/org-lsp (needs curl and tar), then
  -- start it. `:OrgLspDownload` downloads it again, to update it.
  download = true,

  -- The release to download: 'nightly' (built from the latest main), or
  -- a version tag such as 'v0.2.0'.
  release = 'nightly',

  -- The server's options, passed to it as they are.
  settings = {},

  -- How a newly opened file is folded: 'showeverything' (everything
  -- open) or 'overview' (every fold closed). Unset, the server's
  -- `org_startup_folded`, the file's `#+STARTUP:` and its `VISIBILITY`
  -- properties decide, as in Emacs.
  startup_folded = nil,

  -- Fold with the server's folding ranges.
  folding = true,

  -- Turn off Vim's regex syntax for Org once the server's highlighting
  -- arrives.
  replace_syntax = true,

  -- Highlight the code of source and export blocks (`#+begin_src python`,
  -- `#+begin_export html`) and of inline source blocks (`src_python{…}`)
  -- with the tree-sitter parser of its language and its highlight query,
  -- as Emacs's `org-src-fontify-natively` does; a language without a
  -- parser (Emacs Lisp) with its Vim syntax file. A language with neither
  -- stays as it is.
  src_highlight = true,

  -- Conceal what the server marks hidden: link brackets and targets
  -- (`org_link_descriptive`), emphasis markers (`org_hide_emphasis_markers`).
  -- Sets 'conceallevel' 2 in Org windows (a level set before, as by a
  -- `FileType` autocommand, stays); the cursor line shows everything.
  conceal = true,

  -- Indent as Org does, with the server: new lines through 'indentexpr'
  -- (`org-indent-line`, as on RET), and `=` re-indents the lines it moves
  -- over (`org-indent-region`). `gq` still wraps text. How far text goes
  -- follows `org_adapt_indentation`.
  indent = true,

  -- Show files with `org-indent-mode` (`org_startup_indented`, `#+STARTUP:
  -- indent`) indented by level, without changing them, and hide leading
  -- stars (`org_hide_leading_stars`, `#+STARTUP: hidestars`; needs
  -- `conceal`). A line that wraps goes on under its own text, a
  -- headline's title, an item's text ('breakindent'), as Org's
  -- `wrap-prefix`, but without the prefix: Neovim cannot repeat it there.
  virtual_indent = true,

  -- How the agenda and capture buffers open, and how big; see below.
  win_split_mode = 'split',
  win_split_size = nil,

  -- Where the date prompt's calendar opens: 'bottom', 'float', 'cursor';
  -- see below. And the border of a floating calendar.
  calendar_win_mode = 'bottom',
  calendar_border = 'rounded',

  -- Previews of links to images and of LaTeX (`<Leader>oxv`, `<Leader>oxl`),
  -- drawn with `vim.ui.img` (Neovim 0.13): the most lines an image takes
  -- (and columns, `max_width`, on top of `org_image_max_width`), or false
  -- for none. See below.
  images = { max_height = 20 },

  -- Keys by scope; see docs/keys/neovim.org. `false` sets no keys at all.
  mappings = {
    global = {
      ['org.agenda.dispatch'] = '<Leader>oa',
      ['org.capture'] = '<Leader>oc',
      ['org.clock.goto'] = '<Leader>oxj',
      ['org.journal.new.entry'] = '<Leader>jj',
    },
    org = { cycle = '<Tab>', global_cycle = '<S-Tab>' },
    agenda = { quit = 'q' },
  },
})
#+end_src

~mappings~ lists only the keys the plugin needs before the server has
started. The other keys come from the server; [[file:keys/neovim.org][keys/neovim.org]] lists them
all and shows how to change them.

The plugin's options and the server's have types for lua-language-server
(~org_lsp.Config~, ~org_lsp.Settings~, written from the server's own table
of options into ~lua/org-lsp/types.lua~), so with the plugin in its library
they are completed and checked. ~setup()~ is annotated already; annotate
~vim.g.org_lsp~ yourself:

#+begin_src lua
---@type org_lsp.Config
vim.g.org_lsp = {
  settings = { org_log_done = 'time', org_agenda_span = 'day' },
}
#+end_src

~:checkhealth org-lsp~ shows which server the plugin found, where it came
from, and the agenda files.

*** Where the agenda and capture buffers open

~win_split_mode~ says how a window is opened for the agenda and for a
capture buffer. One that is already shown is used again.

| Value              | Opens it                                                                        |
|--------------------+---------------------------------------------------------------------------------|
| ~'split'~          | in a horizontal split (the default)                                             |
| ~'vsplit'~         | in a vertical split                                                             |
| ~'float'~          | in a floating window in the middle of the editor                                |
| ~'current'~        | in the current window                                                           |
| another Ex command | with that command, such as ~'botright split'~, ~'topleft vsplit'~ or ~'tabnew'~ |
| a function         | with the function, which is given the buffer and returns the window it opened   |

#+begin_src lua
require('org-lsp').setup({ win_split_mode = 'float' })

-- A float of your own size.
require('org-lsp').setup({
  win_split_mode = function(bufnr)
    return vim.api.nvim_open_win(bufnr, true, {
      relative = 'editor', row = 2, col = 4, width = vim.o.columns - 8, height = vim.o.lines - 6, border = 'single',
    })
  end,
})
#+end_src

~win_split_size~ says how big that window is: lines for a split, columns
for a vertical one (~'vsplit'~, or a command with ~vsplit~, ~vnew~ or
~vertical~), or, below 1, that part of the editor. A float takes the part
for both its sides (~0.8~ unset), or the lines for its height. Unset, a
split takes half of the window it splits. A function opens its own size.

#+begin_src lua
-- The agenda below, 15 lines high.
require('org-lsp').setup({ win_split_mode = 'botright split', win_split_size = 15 })
-- Beside, a third of the editor wide.
require('org-lsp').setup({ win_split_mode = 'vsplit', win_split_size = 0.33 })
#+end_src

Closing the agenda (~q~) or finishing a capture closes the window that was
opened for it; with ~'current'~, the window goes back to the buffer it
showed before. Going to an entry from the agenda opens the entry's file in
the agenda's window, or, from a floating window, in the window under it.
The window the agenda or a capture buffer was opened from starts with the
same line again when they close, as in Emacs.

*** Where the calendar opens

Commands that ask for a date (~org.deadline~, ~org.schedule~, ~cid~ …) show
the calendar Emacs shows with the prompt. ~calendar_win_mode~ says where.

| Value              | Opens it                                                                                                                                         |
|--------------------+--------------------------------------------------------------------------------------------------------------------------------------------------|
| ~'bottom'~         | in a split along the bottom, as high as the calendar, as Emacs does (the default); from a floating window, in a floating window along the bottom |
| ~'float'~          | in a floating window in the middle of the editor                                                                                                 |
| ~'cursor'~         | in a floating window below the cursor, or above it when there is no room below                                                                   |
| another Ex command | with that command, such as ~'topleft split'~                                                                                                     |
| a function         | with the function, which is given the buffer and returns the window it opened                                                                    |

~calendar_border~ is the border of the floating window (~'float'~,
~'cursor'~), as ~nvim_open_win()~ takes it: ~'rounded'~ unset, ~'none'~ for
none.

The calendar shows three months, as Emacs's does (Emacs has no other
number); the server's ~calendar_months~ option set to ~1~ shows the month of
the selected day alone, which suits a floating window. Under one month the
prompt is on a line of its own and the answer below it
(~10:00 => <2026-10-07 Wed 10:00>~), so the window is not much wider than
the month. Its weeks start on Sunday;
~calendar_week_start_day~ set to ~1~ starts them on Monday, as Emacs's
~calendar-week-start-day~ does:

#+begin_src lua
require('org-lsp').setup({
  calendar_win_mode = 'cursor',
  calendar_border = 'single',
  settings = { calendar_months = 1, calendar_week_start_day = 1 },
})
#+end_src

Picking a time, the minutes move by ~org_time_stamp_rounding_minutes~ (5),
going first to a multiple of it, as ~S-<up>~ on a timestamp does: from
12:44, up is 12:45, then 12:50; down is 12:40.

Once the calendar closes, the window it was asked from shows what it
showed before: the same first line and the cursor on the same text, moved
down with it when the date went in above, as in Emacs, whatever
'scrolloff' and 'splitkeep' are.

*** The clock and the timer in the statusline

While a clock runs, ~require('org-lsp').clock_status()~ returns what
Emacs's mode line shows: the time clocked on the entry, its effort, and its
headline, as in ~[0:25/1:00] (Write the report)~. While the relative timer
or a countdown is on, its value follows (~<0:05:23>~). With neither it
returns an empty string. The plugin redraws the statusline every minute
while a clock runs, every second while a timer runs, and fires the
~User OrgLspClock~ autocommand when the clock starts or stops.

#+begin_src lua
vim.o.statusline = '%f %h%m%r%=%{v:lua.require("org-lsp").clock_status()}  %l,%c'

-- lualine
require('lualine').setup({
  sections = { lualine_x = { function() return require('org-lsp').clock_status() end } },
})
#+end_src

*** Images and LaTeX

Neovim 0.13 draws images in the terminal (~vim.ui.img~, with the Kitty
graphics protocol: Kitty, Ghostty, WezTerm). There the previews of Org
show, as Emacs shows them:

- ~<Leader>oxv~ (~org-link-preview~, ~C-c C-x C-v~) shows the images of the
  links to image files in the current section, or toggles the one of the
  link at the cursor. With a count of 1 links with a description count
  too; 4 takes them away; 16 (or 11) shows those of the whole file, 64
  takes them all away. A file with ~#+STARTUP: inlineimages~ (or
  ~org_startup_with_link_previews~) opens with them.
- ~<Leader>oxl~ (~org-latex-preview~, ~C-c C-x C-l~) shows the LaTeX
  fragments as images, made by Emacs (~latex~ and ~dvipng~, as Org makes
  them, into ~ltximg/~ beside the file), with the same counts. A file with
  ~#+STARTUP: latexpreview~ (or ~org_startup_with_latex_preview~) opens
  with them.

An image shows below the line of its link or fragment, in lines kept free
for it, from where the line's text starts, and follows it as the window
scrolls; it goes when its text does. PNG images show as they are; others
are made PNG with ImageMagick (~magick~ or ~convert~) when it is
installed: read as their extension says (a ~.gif~ file as a GIF), in at
most ten seconds. Older versions of Neovim say that they cannot show
images.

An image keeps its proportions: it shows as wide as
~org_image_actual_width~ says (its own width, a number of pixels, or the
~:width~ of the paragraph's ~#+ATTR_ORG:~, ~300~, ~50%~ or ~0.5~ of the
window's text), at most ~org_image_max_width~ when at its own width (70
columns, Emacs's ~fill-column~), and one larger than ~max_width~ or
~max_height~ (in cells) allows is given only the width or the height it may
take, the terminal working out the other. The lines
kept free below it are those it takes, by the size of the terminal's cells
in pixels, which the terminal tells (Kitty, Ghostty and WezTerm do). Where
it does not (some multiplexers), cells are taken as 10 by 20 pixels; set
their size if images overlap the text below them or leave a gap:

#+begin_src lua
require('org-lsp').setup({ images = { cell = { width = 9, height = 19 } } })
#+end_src

*** org_agenda_sorting_strategy
